🔐 Login Flow Diagram

Alur login untuk 3 role berbeda dalam sistem reservasi camping

USER

Customer Role

Login Flow

1
Akses Halaman Login
GET /masuk → Form login tampil
↓
2
Submit Credentials
POST /masuk dengan email + password → Throttle: 10 attempts/min
↓
3
Authentication
Auth::attempt() verify credentials di database → Check password hash (bcrypt)
↓
4
Session Created
Session regenerate untuk security → Role: user
↓
5
Redirect ke Profile
Redirect /profil → User dashboard
✅ Akses Yang Diizinkan
  • ✓ /profil - Lihat profil & history booking
  • ✓ /reservasi-saya - Daftar reservasi saya
  • ✓ /keranjang - Shopping cart untuk items
  • ✓ /reservasi/buat - Buat booking baru
  • ✓ /reservasi/{id}/batal - Batalkan booking
❌ Tidak Bisa Akses
  • ✗ /staff/* - Inventory management (403 Forbidden)
  • ✗ /admin/* - User management (403 Forbidden)

✅ Akses Yang Diizinkan - FULL ACCESS
  • ✓ Staff Panel: /staff/sewa, /staff/stok, /staff/artikel, /staff/dashboard, /staff/alat
  • ✓ Admin Panel: /admin/akun (user management)
  • ✓ /admin/penilaian-staff - Assess staff performance
  • ✓ Profile page: Lihat semua users + audit logs (30 recent)
  • ✓ POST /admin/akun - Create user
  • ✓ PUT /admin/akun/{user} - Update user
  • ✓ DELETE /admin/akun/{user} - Delete user
  • ✓ POST /admin/staff/{staff}/nilai - Assess staff
⚠️ Pembatasan Admin
  • ✗ Tidak bisa delete last admin - Sistem membutuhkan minimal 1 admin
  • ✓ Audit logs: Semua aksi admin dicatat di AuditLog table
  • ✓ Password confirmation: Update profil & delete account perlu password

🔒 Security & Middleware

  • Guest Middleware: Route /masuk dan /daftar - tolak akses jika sudah login
  • Auth Middleware: Semua protected routes - wajib login untuk akses
  • Role Middleware: Check role user setelah login
    • • User routes: middleware('role:user')
    • • Staff routes: middleware('role:staff,admin') - admin juga bisa akses
    • • Admin routes: middleware('role:admin') - hanya admin
  • Rate Limiting:
    • • Login: 10 attempts per menit
    • • Register: 5 attempts per menit
    • • Availability check: 30 per menit
  • Password Security: Bcrypt hash (Hash::make)
  • Session: Regenerate setelah login sukses
  • CSRF Protection: Token validation di semua POST/PUT/DELETE request
